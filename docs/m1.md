# M1 Implementation Notes

## Contract

M1 requires `SHOPSENSE_M1_MODEL` in `.env`.

The application boundary is:

```text
records.jsonl raw_text
  -> LiteLLM completion(..., response_format={"type": "json_object"})
  -> json.loads()
  -> SupportTicket Pydantic validation
  -> success or bounded repair
  -> parsed_records.jsonl
```

Only `raw_text` is supplied to the extraction prompt. `order_ref`,
`customer_ref`, and `ground_truth` remain outside the model input. The
`ground_truth` block remains in the immutable source data for later evaluation.

## Repair behavior

The implementation follows the Day 1 structured-output pattern:

- The initial response is parsed and validated.
- `JSONDecodeError` and Pydantic validation errors are tracked internally.
- A repair request includes the original raw text, the previous JSON attempt,
  and the error.
- At most two repair calls occur after the initial call.
- A record that still fails receives `status: "failed"`,
  `support_ticket: null`. Internal error details are not persisted in the
  result artifact.

## Data integrity

The application input is a deliberate copy of:

`data-toolkit/capstone-data-toolkit/data/shopsense/intake/records.jsonl`

The generator project and source records are outside the M1 write boundary.

## Non-goals

M1 does not implement tools, order or customer lookups, refunds, RAG, MCP,
memory, LangGraph, multi-agent orchestration, HITL workflows, observability,
or deployment.
