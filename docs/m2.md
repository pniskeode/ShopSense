# ShopSense M2 implementation

## Request flow

M2 requires `SHOPSENSE_M2_MODEL` in `.env`.

The user passes a natural-language question to `shopsense.agent.cli`. Each business function is exposed as a LangChain `@tool`. The agent creates a `ChatLiteLLM`, calls `bind_tools(LANGCHAIN_TOOLS)`, and invokes the bound model with LangChain messages. The model receives the question plus the generated tool schemas. It chooses zero or more tools, the runner executes the selected `BaseTool` with `.invoke()`, and the result is returned in a `ToolMessage`. The loop stops as soon as the model returns an `AIMessage` without tool calls, or after six model iterations.

Supported entry points:

```powershell
& .\.venv\Scripts\python.exe -m shopsense.agent.cli "Track KW-O-000123"
& .\.venv\Scripts\python.exe -m shopsense.agent.cli
```

The programmatic entry point is:

```python
from shopsense.agent.runner import run_agent

answer = run_agent("What is the refund status for KW-O-000086?")
```

## Tool contracts

`lookup_order` joins the order with its customer and product records. `track_shipment` returns shipment tracking fields and the latest scan if multiple scans exist. Missing references are returned as explicit `found: false` business results.

The LangChain wrappers are in `src/shopsense/agent/tools.py`. They call the read-only implementations in `src/shopsense/tools/`, so the tool schema and the data-access logic remain easy to inspect separately.

`refund_or_replace` requires `action` to be `refund` or `replace`. Refund requests return all matching rows, sorted by `requested_on` and `refund_id`, plus status totals. Replace requests always report that replacement is unavailable; they do not claim that a replacement was created or approved.

`get_refund_amount` uses the same complete, sorted refund set. Its `amount_inr` is the sum of rows with `status == "approved"`, representing refunds authorized and awaiting payout. It also returns separate totals for `processed`, `requested`, and `rejected`: processed amounts are already refunded, requested amounts await a decision, and rejected amounts will not be paid.

All five JSON mock tables are loaded read-only from `data/shopsense/mock_api`.

## Safety and boundaries

- The model must use tools for order, shipment, and refund facts.
- It must ask for an order reference when one is required but absent.
- It must preserve not-found results and must not invent operational state.
- The six-iteration cap prevents an unbounded tool loop.
- Tool exceptions are converted into structured tool errors so a model response can recover or terminate cleanly.
