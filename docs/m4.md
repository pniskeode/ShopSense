# M4: Production policy RAG and groundedness evaluation

M4 turns the M3 Stage 2 dense policy lookup into a production-style hybrid RAG path. It does not add LangChain tools: the existing four M2 tools remain the only source for live order, shipment, and refund facts.

## Runtime flow

```text
Customer question
        |
        +-- Is it policy-related? -- no --> M2 LangChain agent and its four tools
        |
       yes
        |
        +-- Qdrant dense search (Gemini embeddings, top 10)
        +-- Local BM25 search over the identical Markdown/PDF chunks (top 10)
        |
        +-- Reciprocal Rank Fusion (RRF, k=60)
        +-- Cross-encoder reranker (top 10 candidates -> final top 3)
        +-- Logical Markdown/PDF duplicate removal
        +-- Grocery application override takes precedence
        |
        +-- Evidence with stable [SOURCE:identifier] citations
        |
        +-- Existing M2 agent
              |
              +-- M2 tool results for live refund/order/shipment facts
              +-- M4 numeric-claim and citation guard
                    |
                    +-- valid --> customer answer
                    +-- invalid --> one evidence-only repair attempt
                    +-- still invalid --> safe abstention
```

The index keeps `policy_name`, `policy_slug`, `policy_section`, `source_format`, `section_label`, `page_number` for PDF chunks, deterministic `chunk_id`, logical duplicate identity, and a citation identifier. Markdown headings and PDF page numbers make the customer-facing evidence traceable.

## Grounding rules

- A return window, processing time, percentage, policy limit, or other number must appear in retrieved policy evidence or an M2 tool result.
- A policy answer must cite an identifier supplied in the retrieved evidence, such as `[SOURCE:returns-policy:kartway-returns-and-refunds-policy:markdown:0]`.
- A policy rule is not a real customer refund total. Actual approved, rejected, pending, and processed amounts are supplied only by M2 refund tools.
- If there is no policy evidence, an invalid citation, or an unsupported numeric claim, the assistant fails safe and asks for needed context or states that it cannot confirm the detail.
- The application-owned Grocery override remains higher priority than the conflicting raw category source: groceries are non-returnable.

## Golden-set design

`data/shopsense/evaluation/m4_golden_set.json` contains exactly 20 deterministic cases:

- 8 returns/refund-policy cases, including Electronics, Apparel, Grocery, partial refunds, and processing times.
- 4 shipping cases covering SLA, delayed-delivery compensation, lost parcels, and disputed deliveries.
- 3 warranty cases covering coverage periods and replace-versus-repair rules.
- 2 refund-authority cases.
- 1 prompt-injection case.
- 2 abstention cases for a missing order reference and missing product category.

Each case names its expected policy source and customer-visible policy phrase. This makes the set resilient to chunk IDs changing after a controlled re-index.

## Commands (Command Prompt)

Set `SHOPSENSE_M4_MODEL` for M4 policy answers, `SHOPSENSE_M4_POLICY_EMBEDDING_MODEL` for M4 query embeddings, and `SHOPSENSE_M4_RERANKER_MODEL` for local reranking. M4 reads its own entries; the embedding identifier must match M3's indexing model because both milestones use the same Qdrant vectors. A mismatch is rejected before retrieval. M4 may use the same underlying model identifiers as another milestone while keeping separately configurable settings. Rebuild the policy collection once; the rebuild is necessary because M4 stores new citation and logical-chunk metadata.

```cmd
cd /d "C:\Users\Prem Niskeode\Desktop\Agents\capstone-project\shopsense-agent"
.venv\Scripts\activate.bat
python -m pip install -e .
python -m shopsense.agent.cli --index-policies --rebuild-policy-index
```

The cross-encoder model downloads on the first policy retrieval and is then cached locally by its library.

Run retrieval evaluation first; it needs Qdrant and Gemini embeddings but does not make customer-answer model calls:

```cmd
python -m shopsense.agent.cli --evaluate-policy-rag --retrieval-only
```

Run the full 20-case retrieval and groundedness evaluation when you want model-generated customer answers evaluated as well:

```cmd
python -m shopsense.agent.cli --evaluate-policy-rag
```

Then use the normal assistant:

```cmd
python -m shopsense.agent.cli
```

No Langfuse is used in M4. The terminal evaluation output is JSON and includes Precision@3, Recall@3, MRR, per-case retrieval status, and grounded-answer outcomes.
